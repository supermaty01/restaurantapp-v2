# 08 — UI

## Punto de partida y su límite

Existe un rediseño trabajado en Claude Design:

```
Proyecto: RestaurantApp Refresh
https://claude.ai/design/p/0e9f7748-b3ab-4bad-9cbc-555f93c81d7a?file=RestaurantApp+Refresh.dc.html
Importación: claude_design MCP (https://api.anthropic.com/v1/design/mcp, auth via /design-login)
```

**Decisión: el rediseño se usa como referencia visual (lenguaje, tokens, tono), no como estructura.** Se diseñó para la app v1 y no contempla la mayoría de lo que trae la v2: feed, perfiles, amigos, asistente conversacional, etiquetado de personas, estados de sync. Hay demasiada superficie nueva para encajarla a la fuerza en una navegación pensada para otra app. **La arquitectura de información se rediseña de cero**; del proyecto de diseño se toma el sistema visual.

## Dos entregables distintos

### 1. Sistema de diseño (del rediseño existente)

Tokens (color, tipografía, espaciado, radios, sombras) en `tailwind.config.js` + catálogo de componentes base en `apps/mobile/components/ui`: `Button`, `Card`, `Input`, `Sheet`, `Badge`, `Avatar`, `Chip`, `EmptyState`, `Skeleton`. Pares claro/oscuro desde el día uno (la v1 ya soporta dark mode y es requisito).

### 2. Arquitectura de información (nueva)

La v1 es una app de **gestión** (listas CRUD: restaurantes / platos / visitas / tags / mapa). La v2 es una app de **diario + social + asistente**, y eso cambia qué merece estar en el primer nivel.

Propuesta de navegación (a validar al iniciar la fase):

| Tab                 | Contenido                                                                                                                        |
| ------------------- | -------------------------------------------------------------------------------------------------------------------------------- |
| **Feed**            | Actividad de amigos. Para usuarios sin cuenta: se convierte en "Inicio" con actividad propia reciente y accesos rápidos          |
| **Explorar / Mapa** | Mapa + búsqueda + filtros. Es la vista natural de "mis sitios"                                                                   |
| **➕ Registrar**    | Acción central: entrada por voz/texto al asistente, o formulario manual. El registro es el corazón de la app y hoy está a 3 taps |
| **Mis datos**       | Listas de restaurantes/platos/visitas (lo que hoy es toda la app), con tags                                                      |
| **Perfil**          | Perfil propio, amigos, ajustes, sync, backups                                                                                    |

Notas de esta propuesta:

- Las listas CRUD **bajan de nivel** (siguen completas, pero dejan de ser la app entera).
- El **registro sube a acción central**, con el asistente como camino primario y el formulario como respaldo — coherente con que el caso de uso real es "estoy comiendo, quiero apuntarlo sin fricción".
- **Sin cuenta, la navegación no se rompe**: Feed pasa a ser Inicio y Perfil muestra ajustes + invitación a crear cuenta. Nunca un tab muerto pidiendo login.

**Abierto:** validar esta estructura al iniciar fase 6 (posiblemente Feed y Explorar se fusionen; posiblemente Mis datos viva dentro de Perfil).

## Superficies nuevas a diseñar

Perfil propio y de amigos · búsqueda de usuarios y solicitudes · feed · etiquetado de personas en visitas · pantalla del asistente (chat + micrófono + tarjetas de confirmación) · wizard de primer login y vinculación de datos · estados de sync · preview web de share links (HTML del Worker, mismo lenguaje visual) · **carrusel y visor de imágenes propios** (ver [11](11-dependencias.md)).

## Criterios

- Accesibilidad: contraste AA, targets ≥44px, soporte de tamaños de fuente del sistema, labels de accesibilidad (lo verifica `eslint-plugin-jsx-a11y`, ver [12](12-calidad.md)).
- Los formularios conservan su lógica (react-hook-form + zod) y ganan **prefill por parámetros** — prerrequisito del agente IA ([07](07-asistente-ia.md)).
- Presupuesto de dependencias: NativeWind + componentes propios + iconos. **Ninguna librería de UI nueva** ([11](11-dependencias.md)).
